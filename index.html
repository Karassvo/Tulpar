01
Week 1 · Introduction to AI

The Land of Agents

Before any algorithm, we must say who is acting, in what world, and what counts as success.

Bürkit landed on Tulpar's antenna. "Tell me what you are." "A robot," said Tulpar. "No. You are an agent. You sense the world, and you act on it. Your trouble this morning was not your wheels. It was the way you choose."

Agents and environments

An agent is anything that perceives its environment through sensors and acts on it through actuators. A percept is what the sensors deliver at one moment. The full list of everything the agent has perceived so far is its percept history. The agent's behaviour is a mapping from percept history to action, called the agent function; the program that implements it is the agent program.

Rationality

A rational agent chooses the action that is expected to maximise its performance measure, given its percept history and what it knows about the world. Rational does not mean all-knowing (omniscient). If a rational driver brakes for a shadow that turns out to be harmless, the choice was still rational, because it was the best choice given the evidence at that moment. We judge rationality by the information available before the action, not by hindsight.

PEAS: describe the job before the algorithm

PEAS stands for Performance measure, Environment, Actuators, Sensors. Writing these four lines turns a vague wish ("make the robot smart") into a clear specification.

PEASSelf-driving carTulpar, the delivery robot
PerformanceSafety, travel time, comfort, legal drivingDocuments delivered, delivery time, no collisions, battery used
EnvironmentRoads, traffic, pedestrians, weatherCorridors, rooms, doors, students, lifts
ActuatorsSteering, throttle, brakes, signalsWheels (forward, turn left, turn right, stop), gripper
SensorsCameras, radar, lidar, GPSObstacle sensor, door sensor, wheel odometer, room-number camera

Four agent architectures

Tulpar's morning failure is a classic case. Its rules were "if obstacle ahead, turn right; otherwise go forward". These rules react only to the current percept. They cannot remember a dead end and they do not know where Room B is, so nothing guarantees arrival. Tulpar needs at least a model of the building and a goal, which leads directly to search in Chapter 2.

Python: a simple reflex agent

def greenhouse_agent(temperature, humidity):
    if temperature < 18:
        return "Heater ON"
    elif temperature > 28:
        return "Fan ON"
    elif humidity > 80:
        return "Dehumidifier ON"
    else:
        return "No action"

print(greenhouse_agent(24, 85))   # Dehumidifier ON
print(greenhouse_agent(17, 90))   # Heater ON: the first matching rule wins

A greenhouse is a good fit for a reflex agent: the right action depends only on the current reading. Notice that the order of the rules decides what happens when two conditions are true at once.

Did you know?

The phrase "artificial intelligence" comes from a 1955 proposal by John McCarthy, Marvin Minsky, Nathaniel Rochester and Claude Shannon for a summer workshop at Dartmouth College in 1956. That workshop is usually counted as the birth of AI as a field.

Myth

A rational agent never makes mistakes.

Fact

A rational agent makes the best choice it can justify with the evidence it has. With noisy sensors, a rational choice can still have a bad outcome.

Remember
  • PEAS defines the task; the environment's properties shape the design.
  • Rationality means maximising expected performance, not being right every time.
  • Reflex → model-based → goal-based → utility-based: more reasoning, more cost.

Week 2 · Uninformed search, A* and heuristics

The Land of Paths

When the world is known and actions are predictable, intelligence becomes a question of which possibility to explore next.

The first land was a maze of roads between villages. "How do I find the way?" asked Tulpar. Bürkit rose high into the sky. "From up here I cannot see the roads you will take, but I can see how far you are from the goal in a straight line. That guess is a gift. Use it wisely and you will search less."

What is a search problem?

State space
All the situations the agent can be in. For a route, a state can be just a location (x, y). We keep only the details needed for planning; this is abstraction.
Initial state
Where the problem starts, for example Astana.
Actions and successors
The legal moves from a state and the states they lead to (the transition model).
Goal test
A check that tells whether a state is a goal, for example "is the city Almaty?"
Path cost
The sum of step costs along a path, such as kilometres or minutes.
Solution
A sequence of actions from the initial state to a goal. An optimal solution has the lowest path cost.

A state-space graph has each state once, with arrows for actions. A search tree is a "what if" tree of plans: the root is the start, and every node stands for a whole path from the start. The same state can appear many times in a tree. The set of nodes waiting to be expanded is called the frontier (or fringe). Every search algorithm in this chapter follows the same loop; they differ only in which frontier node they expand next.

Worked example · why BFS is not enough

Edges: A→B costs 2, A→C costs 8, B→F costs 10, C→F costs 1. Both routes to F have two steps.

  1. BFS sees two paths of equal depth and may return A→B→F.
  2. UCS compares total costs: A→B→F = 2 + 10 = 12, A→C→F = 8 + 1 = 9.
  3. UCS returns A→C→F because it always expands the cheapest path so far.

A*: past cost plus a smart guess

UCS asks "what have I paid so far?". A* also asks "how much is probably left?". It uses three numbers for every node n:

f(n) = g(n) + h(n) · g = exact cost so far · h = estimated cost to the goal · f = estimated total

The estimate h is a heuristic. A heuristic is admissible if it never overestimates: 0 ≤ h(n) ≤ h*(n), where h*(n) is the true cheapest cost to a goal. Straight-line distance on a map is admissible, because no road is shorter than a straight line. On a grid where you move up, down, left and right, Manhattan distance |Δx| + |Δy| is admissible. A heuristic is consistent if h(n) ≤ cost(n, n′) + h(n′) for every step; consistency guarantees optimality even when we avoid re-expanding visited states.

A* expands B. It has already cost more than A, but its estimated total is the smallest. A* is willing to pay more now when the whole route looks better.

Two useful facts: if h(n) = 0 everywhere, then f = g and A* behaves exactly like UCS. If h overestimates, A* may run faster but can return a route that is not optimal.

Why is A* optimal with an admissible heuristic? (proof sketch)

Let A be the optimal goal and B a worse goal on the frontier. Some node n on the optimal path to A is also on the frontier. Then f(n) = g(n) + h(n) ≤ g(A) because h never overestimates, and g(A) = f(A) because h = 0 at a goal. Since B is worse, f(A) = g(A) < g(B) = f(B). So f(n) ≤ f(A) < f(B): every node on the path to A is expanded before B, and A is returned first.

Python: breadth-first search

from collections import deque

def bfs(graph, start, goal):
    queue = deque([(start, [start])])      # frontier holds (state, path)
    visited = {start}
    while queue:
        state, path = queue.popleft()      # FIFO: oldest plan first
        if state == goal:
            return path
        for nxt in graph[state]:
            if nxt not in visited:
                visited.add(nxt)
                queue.append((nxt, path + [nxt]))
    return None

graph = {"A":["B","C"], "B":["D","E"], "C":["F"], "D":[], "E":["G"], "F":[], "G":[]}
print(bfs(graph, "A", "G"))   # ['A', 'B', 'E', 'G']

Change popleft() to pop() and the queue becomes a stack: that one change turns BFS into DFS. Replace the queue with heapq ordered by cost and you get UCS; order by g + h and you get A*.

Did you know?

A* was published in 1968 by Peter Hart, Nils Nilsson and Bertram Raphael at the Stanford Research Institute. It was created for Shakey, one of the first mobile robots that could plan its own moves. Map apps, game characters and warehouse robots still use descendants of it.

Myth

A* always finds the best route, whatever heuristic you give it.

Fact

A* is guaranteed optimal only when the heuristic never overestimates (admissible), and for graph search, when it is consistent.

Remember
  • One loop, different frontier rules: FIFO = BFS, LIFO = DFS, cheapest g = UCS, cheapest g + h = A*.
  • BFS finds the fewest steps; UCS and A* find the lowest cost.
  • A good admissible heuristic keeps A* optimal and makes it explore far less.

Week 3 · Local search and constraint satisfaction

The Land of Hills and Puzzles

Sometimes the path does not matter at all. Only the final arrangement does.

In the third land Tulpar became a courier in Astana. It had to visit QAIRU, Bäiterek, EXPO, the Botanical Garden, Khan Shatyr, the National Museum, the railway station and the airport, then return. Its first route was 76 km. "There are thousands of possible orders," it sighed. "Then do not search for a path to an answer," said Bürkit. "Take any complete answer and keep improving it. Swap two stops. Is it shorter? Keep it." After one swap, the route was 68 km.

Local search: improve a complete configuration

In Chapter 2 the answer was a path. In problems like the travelling salesperson problem (TSP), n-queens or a timetable, the answer is a complete arrangement and the way we reached it is irrelevant. Local search keeps one (or a few) complete candidate solutions and moves to better neighbours. It uses very little memory, because it does not store a frontier.

State
One complete candidate, e.g. a full delivery route.
Neighbour
A small change to it: swap two cities, reverse a segment (2-opt), move one queen in its column.
Objective function
One number that scores a state: total route length to minimise, or "fitness" to maximise.

Hill climbing and its traps

Hill climbing repeatedly moves to the best neighbour and stops when no neighbour is better. On the list of values [1, 3, 5, 8, 6, 4, 2], starting at index 0, it climbs 1 → 3 → 5 → 8 and stops, because both neighbours of 8 (5 and 6) are lower. That is fast and greedy. It can also get stuck:

  • Random-restart hill climbing runs hill climbing from several random starts and keeps the best result. Different starts fall into different "basins", so one of them may reach the global peak.
  • Simulated annealing sometimes accepts a worse move, with probability eΔE/T, where ΔE < 0 is how much worse the move is and T is a "temperature" that slowly decreases. Early on (high T) it explores; later (low T) it behaves greedily. The name comes from metallurgy, where metal cooled slowly forms a stronger structure.
  • Local beam search keeps k states at once and chooses the best k from all their neighbours, so a good region found by one search attracts the others.
  • Genetic algorithms keep a population, select the fittest, combine pairs (crossover) and add random changes (mutation), generation after generation.
  • Gradient descent works in continuous spaces: x ← x − α ∇f(x), stepping against the slope with step size α (the learning rate). This same idea trains the neural networks of Chapter 9.
Worked example · annealing acceptance

A neighbour is worse by ΔE = −2.

  1. At high temperature T = 10: P(accept) = e−2/10 = e−0.2 ≈ 0.82. The bad move is usually accepted, so the search can cross a valley.
  2. At low temperature T = 1: P(accept) = e−2 ≈ 0.14. The search is now mostly greedy.
  3. A better move (ΔE > 0) is always accepted. In the courier story, 76 km → 68 km is an improvement, so every method accepts it.
import random, math

def anneal(values, start, T=10.0):
    current = start
    while T > 0.1:
        nxt = min(max(current + random.choice([-1, 1]), 0), len(values) - 1)
        dE = values[nxt] - values[current]          # maximisation
        if dE > 0 or random.random() < math.exp(dE / T):
            current = nxt
        T *= 0.95                                    # cooling schedule
    return current

landscape = [1, 3, 5, 4, 2, 6, 9, 7, 3]
print(anneal(landscape, 0))   # often ends at index 6 (value 9), beyond the local peak 5

The result is random. Run it several times: hill climbing from index 0 always stops at 5, while annealing often reaches 9.

Constraint satisfaction problems (CSP)

Some puzzles are best described by rules rather than by a path. A CSP has variables, a domain of possible values for each, and constraints that say which combinations are allowed. A solution assigns a value to every variable without breaking any constraint.

Example · a small QAIRU timetable

Variables: the lectures AI, Math, Physics, Python. Domain: time slots {Mon 9:00, Mon 11:00, Tue 9:00}. Constraints: AI and Python share a teacher, so AI ≠ Python; Math and Physics use the same room, so Math ≠ Physics; the same student group takes AI and Math, so AI ≠ Math.

  1. Backtracking search assigns one variable at a time and goes back as soon as a constraint fails.
  2. MRV (minimum remaining values): pick the variable with the fewest legal values left; it is the most likely to fail, so we find out early.
  3. Forward checking: after AI = Mon 9:00, remove Mon 9:00 from Python and Math at once.
  4. One solution: AI = Mon 9:00, Math = Mon 11:00, Physics = Mon 9:00, Python = Mon 11:00.

Large real timetables are often solved with local search on a cost such as Cost = 100·T + 100·R + 20·S + 5·W (teacher clashes, room clashes, student-group clashes, wasted gaps), where hard constraints get large weights. The min-conflicts heuristic, which moves a variable to the value with the fewest conflicts, is very effective on puzzles such as n-queens.

Did you know?

According to Russell and Norvig's textbook, the min-conflicts method solves even the million-queens problem in about 50 steps on average after its initial assignment.

Myth

Simulated annealing is just random guessing.

Fact

It is guided search. It always accepts improvements and accepts bad moves less and less often as the temperature falls.

Remember
  • Local search improves a whole configuration and keeps almost no memory.
  • Local maxima, plateaus and ridges trap hill climbing; restarts and annealing help.
  • A CSP is variables + domains + constraints; backtracking with MRV and forward checking solves small ones.

Week 4 · Adversarial search and game trees

The Land of Rivals

When another agent wants the opposite of what you want, the world fights back.

In the fourth land a rival robot challenged Tulpar to togyz kumalak, the Kazakh board game of "nine stones", played on two rows of nine holes. Tulpar picked the move that led to the biggest possible score and lost in five turns. "You chose as if your rival would help you," said Bürkit. "Assume instead that it will always make the move that hurts you most."

Games as search problems

Togyz kumalak, chess and tic-tac-toe are deterministic, two-player, perfect-information, zero-sum games. Zero-sum means one player's gain is the other's loss, so a single number can describe each outcome: MAX wants it high, MIN wants it low. A game is defined by an initial state, whose turn it is, the legal actions, the transition model, a terminal test (is the game over?) and a utility for terminal states, such as +1 win, 0 draw, −1 loss. In a general-sum game, such as a negotiation, players have separate utilities and may partly cooperate.

Minimax

The minimax value of a state is the best utility MAX can guarantee if both players play perfectly:

V(s) = U(s) if s is terminal · V(s) = max over children if MAX moves · V(s) = min over children if MIN moves

Why doesn't MAX aim for the 14 in the right branch? Because MIN chooses there, and MIN would pick 2. Minimax evaluates what MAX can guarantee, not the largest number visible somewhere in the tree. The cost is high: with branching factor b and depth m, minimax looks at O(bm) states. Chess has roughly 35 legal moves per position, so full search is impossible.

Alpha–beta pruning

Alpha–beta returns the same decision as minimax while skipping branches that cannot change it. It carries two numbers down the tree:

α (alpha)
The best value MAX can already guarantee on the current path. Starts at −∞.
β (beta)
The best value MIN can already guarantee on the current path. Starts at +∞.
Prune when α ≥ β
The remaining children cannot affect the choice at the root.
Worked example · the tree above
  1. Left MIN node: sees 3, 12, 8 → value 3. Back at the root, α = 3.
  2. Middle MIN node: its first leaf is 2, so this node's value is at most 2. MAX already has 3 elsewhere, so 2 ≤ α: stop. Leaves 4 and 6 are never examined.
  3. Right MIN node: 14, then 5, then 2. No cut is possible until the last leaf, so all three are examined. The root value is still 3.

Move ordering matters: if the best moves are tried first, bounds tighten sooner and alpha–beta can examine about O(bm/2) nodes, which effectively doubles the depth searchable in the same time.

Real games: depth limits and evaluation functions

Real programs stop at a depth limit and score the position with an evaluation function, often a weighted sum of features: Eval(s) = w₁f₁(s) + w₂f₂(s) + … For chess the features might be material, mobility, king safety and centre control. A danger of depth limits is the horizon effect: a disaster just beyond the depth limit stays invisible, so a position looks good one move before it collapses.

Expectimax: when the opponent is chance

If outcomes depend on dice, slipping wheels or a random ghost in Pac-Man, worst-case thinking is too pessimistic. Expectimax replaces MIN nodes with chance nodes that take the probability-weighted average: V(chance) = Σ P(s′)·V(s′).

Worked example · a chance node

Outcomes 8, 24 and −12 with probabilities 1/2, 1/3 and 1/6: (1/2)·8 + (1/3)·24 + (1/6)·(−12) = 4 + 8 − 2 = 10.

MinimaxExpectimax
Uncontrolled nodeMIN: worst case for usCHANCE: average outcome
Good model ofA clever, hostile opponentDice, noise, random behaviour
Risk if wrongToo pessimistic against a random worldDangerously optimistic against a real adversary
def alphabeta(node, alpha, beta, maximizing):
    if isinstance(node, int):              # leaf = terminal utility
        return node
    if maximizing:
        value = float("-inf")
        for child in node:
            value = max(value, alphabeta(child, alpha, beta, False))
            alpha = max(alpha, value)
            if alpha >= beta: break          # prune
        return value
    value = float("inf")
    for child in node:
        value = min(value, alphabeta(child, alpha, beta, True))
        beta = min(beta, value)
        if alpha >= beta: break
    return value

tree = [[3, 12, 8], [2, 4, 6], [14, 5, 2]]
print(alphabeta(tree, float("-inf"), float("inf"), True))   # 3
Did you know?

IBM's Deep Blue defeated world chess champion Garry Kasparov in 1997. Checkers was "solved" in 2007 by Jonathan Schaeffer's team: with perfect play from both sides it is a draw. In 2016 DeepMind's AlphaGo beat Lee Sedol at Go 4–1 by combining tree search with neural-network evaluation.

Myth

Alpha–beta pruning is a shortcut that sometimes gives a worse move than minimax.

Fact

Alpha–beta always returns the same root value and move as minimax. It only skips work that cannot change the answer.

Remember
  • Minimax backs values up the tree: MIN takes the minimum, MAX the maximum.
  • Alpha–beta prunes when α ≥ β and never changes the result.
  • Use evaluation functions at a depth limit; use expectimax when uncertainty is chance, not an enemy.

Week 5 · Markov decision processes and reinforcement learning

The Land of Long Journeys

When actions have uncertain results and rewards come later, a single path is no longer enough. You need a policy.

Winter came to the fifth land, and Astana's pavements turned to ice. When Tulpar tried to move right, it went right 80% of the time, but slipped up 10% of the time and down 10% of the time. Its carefully planned path was useless after the first slip. "Stop memorising paths," said Bürkit. "Learn what to do in every place you might end up."

The MDP model

A Markov decision process (MDP) describes sequential decisions under uncertainty with five parts:

States S
What the agent needs to know, e.g. grid position, or (battery charge, price, hour).
Actions A
The available choices: UP, DOWN, LEFT, RIGHT; or CHARGE, HOLD, DISCHARGE.
Transition model T(s′ | s, a)
The probability of reaching s′ after doing a in s. "Markov" means it depends only on the current state, not on the history.
Reward R(s, a, s′)
Immediate feedback, e.g. +10 at the goal, −10 in danger, −1 per step.
Discount γ (gamma)
A number between 0 and 1 that sets how much future rewards matter.

The answer to an MDP is a policy π: a rule that says what to do in each state, π(s) = a. If Tulpar slips, the policy still tells it what to do next. Search returns a path; an MDP returns a policy.

Return, value and the Bellman equation

The agent maximises the return, the discounted sum of future rewards: G = R₁ + γR₂ + γ²R₃ + … With rewards 5, 10, 20 and γ = 0.9, G = 5 + 0.9·10 + 0.81·20 = 30.2. The discount factor changes a lot: a reward of 100 that arrives 10 steps later is worth about 0.10 today if γ = 0.5, 34.87 if γ = 0.9, and 90.44 if γ = 0.99.

Reward is not value. Reward is what you get right now. The value V(s) is the expected return from state s onward. A state next to the goal may have reward 0 and still be very valuable. The Q-value Q(s, a) is the expected return if you take action a in s and then act well. The Bellman equation breaks the future into "now + later":

V*(s) = max over a of Σ T(s′|s,a) · [ R(s,a,s′) + γ · V*(s′) ]
Worked example · Bellman on ice

Moving RIGHT reaches a GOOD state (V = 10) with probability 0.8 and a BAD state (V = −5) with probability 0.2. Each step costs −1 and γ = 0.9.

  1. Good branch: 0.8 × (−1 + 0.9 × 10) = 0.8 × 8 = 6.4
  2. Bad branch: 0.2 × (−1 + 0.9 × (−5)) = 0.2 × (−5.5) = −1.1
  3. Q(s, RIGHT) = 6.4 − 1.1 = 5.3

Planning when the model is known

  • Value iteration starts with V = 0 and applies the Bellman update to every state, again and again, until values stop changing. Value spreads backwards from the goal. In a 4-state chain with goal value 10, step cost −1 and γ = 0.9, the values become 8, then 6.2, then 4.58 as information travels back one state per sweep.
  • Policy iteration alternates two steps: evaluate the current policy (compute Vπ), then improve it by choosing in each state the action with the best one-step look-ahead. It stops when the policy no longer changes.

Reinforcement learning: when the model is unknown

Often nobody knows T or R exactly. What is the probability that a motor fails tomorrow given its vibration? Reinforcement learning (RL) learns from experience instead: the agent acts, sees (s, a, r, s′) and updates its estimates. There are no labels saying "this was the right action", and feedback can be delayed by many steps.

RL has to balance exploration (try something new to learn more) and exploitation (use what seems best now). The simplest method is ε-greedy: with probability ε take a random action, otherwise the best known one.

Temporal-difference (TD) learning updates an estimate using one step of experience and the next estimate (this reuse of an estimate is called bootstrapping). Q-learning applies this to action values:

Q(s,a) ← Q(s,a) + α · [ r + γ · maxa′ Q(s′,a′) − Q(s,a) ]
Worked example · one Q-learning update

Q(A, RIGHT) = 4, reward r = 2, best next value max Q(B, ·) = 8, γ = 0.9, α = 0.5.

  1. Target = 2 + 0.9 × 8 = 9.2
  2. TD error = 9.2 − 4 = 5.2 (better than expected)
  3. New Q = 4 + 0.5 × 5.2 = 6.6
SymbolNameQuestion it answers
αLearning rateHow much should one new experience change my estimate?
γDiscount factorHow much do future rewards matter now?
εExploration rateHow often should I try something other than my current best?

SARSA is almost the same as Q-learning, but its target uses the action the agent actually takes next, Q(s′, a′), instead of the maximum. That makes SARSA on-policy (it learns the value of how it really behaves, exploration included) and Q-learning off-policy (it learns the value of the greedy policy while exploring).

Beyond tables: deep reinforcement learning

A battery controller with 10 charge levels, 20 prices, 20 demand levels, 20 solar levels and 24 hours already has 1,920,000 states. Tables cannot scale to images or continuous sensors. Deep Q-Networks (DQN) replace the table with a neural network that estimates Q(s, a). Policy-gradient methods learn the policy directly, which suits continuous actions like steering. Actor–critic methods combine both: the actor chooses actions, the critic judges them.

Safety note. A badly designed reward can be "hacked": the agent maximises the number, not what we meant. Real systems keep hard safety limits outside the reward, train in simulators first, and keep a human able to override.

Did you know?

In 1992 Gerald Tesauro's TD-Gammon learned to play backgammon at a strong level mainly by playing against itself with TD learning. In 2015 DeepMind's DQN learned to play dozens of Atari games directly from screen pixels.

Myth

An RL agent should always take the action with the highest reward right now.

Fact

RL maximises long-term return. Paying for maintenance today (−15) can be right if it prevents a −200 breakdown later.

Remember
  • An MDP = states, actions, transitions, rewards, discount. Its solution is a policy.
  • Bellman: value now = reward + discounted value later. Value and policy iteration use it when the model is known.
  • Q-learning learns from experience: move Q partway (α) toward r + γ·max Q(s′, ·).

Week 6 · Probability and Bayesian networks

The Land of Fog

Real sensors are noisy. Probability lets an agent hold a degree of belief instead of a false certainty.

Fog covered the sixth land. A medical drone landed next to Tulpar, shaking. "My test says the shepherd is ill! The test is 95% accurate!" Bürkit closed his eyes. "And how many shepherds in this valley are ill at all?" "One in a hundred," said the drone. "Then sit down. Let us count before we panic."

The language of uncertainty

Random variable
A quantity with uncertain value, e.g. Rain ∈ {true, false} or Weather ∈ {sunny, cloudy, rainy}.
Distribution
Probabilities for every value, adding to 1: sunny 0.5, cloudy 0.3, rainy 0.2.
Joint probability P(A, B)
The probability that A and B happen together.
Conditional P(A | B)
The probability of A once we know B: P(A | B) = P(A, B) / P(B).
Worked example · conditioning shrinks the world

Over 100 days: rain and heavy traffic on 24 days, rain and light traffic on 6, no rain and heavy traffic on 21, no rain and light traffic on 49.

  1. P(Heavy) = (24 + 21) / 100 = 45%.
  2. P(Heavy | Rain): look only at the 30 rainy days. 24 of them have heavy traffic: 24 / 30 = 80%.

Conditioning changes the denominator from all days to only the days that match the evidence.

Bayes' theorem

Bayes' theorem reverses a conditional probability. It turns "how likely is this evidence if the hypothesis is true?" into "how likely is the hypothesis now that I see the evidence?"

P(H | E) = P(E | H) · P(H) / P(E) where P(E) = P(E|H)·P(H) + P(E|¬H)·P(¬H)

P(H) is the prior, P(E | H) the likelihood, P(E) the evidence and P(H | E) the posterior.

Worked example · the drone's test

Prevalence P(D) = 1%, sensitivity P(+ | D) = 95%, false-positive rate P(+ | ¬D) = 10%. Imagine 10,000 shepherds:

  1. 100 are ill; 95 of them test positive.
  2. 9,900 are healthy; 10% of them, 990, also test positive.
  3. P(D | +) = 95 / (95 + 990) = 95 / 1,085 ≈ 8.76%.

A positive result raises the risk from 1% to about 9%. That is worth a second test, not a panic. Forgetting the small prior is called the base-rate fallacy.

Bayesian networks

A full joint table over n true/false variables needs 2n numbers, which is impossible for large n. A Bayesian network is a directed acyclic graph (arrows, no loops) where each node is a variable and each node stores a conditional probability table (CPT) given its parents. The joint distribution factorises into small pieces:

P(X₁, …, Xₙ) = Π P(Xᵢ | Parents(Xᵢ)) e.g. P(R, S, W) = P(R) · P(S | R) · P(W | R, S)
Worked example · inference by enumeration

The grass is wet. Did it rain? Sum over the hidden Sprinkler variable, then normalise.

  1. Rain = true: 0.20 × [0.01 × 0.99 + 0.99 × 0.80] = 0.20 × 0.8019 = 0.16038
  2. Rain = false: 0.80 × [0.40 × 0.90 + 0.60 × 0] = 0.80 × 0.36 = 0.288
  3. P(Rain | Wet) = 0.16038 / (0.16038 + 0.288) ≈ 35.8%, up from the prior of 20%.

Three small patterns explain how evidence flows through a network. In a chain A → B → C and a fork A ← B → C, knowing B blocks the flow between A and C (they become conditionally independent given B). In a collider A → B ← C, it is the opposite: A and C are independent until B is observed. This is explaining away: if the grass is wet and you learn the sprinkler was on, rain becomes less necessary as an explanation.

Exact and approximate inference

  • Enumeration sums over every hidden variable, as above. It is exact but repeats work.
  • Variable elimination sums out one variable at a time and stores intermediate factors. The elimination order affects speed.
  • Rejection sampling simulates the network many times and keeps only samples where the evidence is true. It wastes samples when the evidence is rare.
  • Likelihood weighting fixes the evidence and weights each sample by how likely that evidence was.
  • Gibbs sampling repeatedly resamples one non-evidence variable given all the others.
import random
random.seed(42)
def p_wet(r, s): return {(1,1):.99, (1,0):.80, (0,1):.90, (0,0):0.0}[(r, s)]

kept = rain_and_wet = 0
for _ in range(100_000):
    rain = random.random() < 0.20
    sprinkler = random.random() < (0.01 if rain else 0.40)
    wet = random.random() < p_wet(rain, sprinkler)
    if wet:                       # reject samples that contradict the evidence
        kept += 1
        rain_and_wet += rain
print(rain_and_wet / kept)           # 0.356, close to the exact 0.3577
Did you know?

Judea Pearl developed Bayesian networks in the 1980s and received the 2011 Turing Award, the highest prize in computer science, for his work on probabilistic and causal reasoning.

Myth

If a 95%-sensitive test is positive, there is a 95% chance you have the disease.

Fact

P(+ | D) and P(D | +) are different. With a rare disease the answer can be under 10%, as the worked example shows.

Remember
  • Posterior ∝ likelihood × prior. Always include the false-positive pathway in P(E).
  • A Bayesian network = DAG + CPTs; it stores small local tables instead of one huge joint table.
  • Exact inference sums and normalises; sampling estimates the same answer by counting.

Week 7 · Hidden Markov models and sequential inference

The Land of Hidden Things

Some things can never be seen directly, only guessed from the clues they leave over time.

In the seventh land Tulpar's left wheel motor began to feel strange. It could not look inside the motor; it had only a temperature sensor that said NORMAL or HIGH. The sensor said HIGH. "Am I broken?" Bürkit tilted his head. "One reading is a rumour. Two readings in a row are a story. Let us follow the story, one step at a time."

Markov chains

A Markov chain describes how a state changes over time. The Markov assumption says the next state depends only on the current one: P(Xt+1 | Xt, Xt−1, …) = P(Xt+1 | Xt). The probabilities are stored in a transition matrix whose rows add up to 1.

Healthy0.900.10

Left: transition probabilities T. Right: emission probabilities O, how likely each reading is in each hidden state. Note that P(HIGH | Faulty) = 0.7 is not P(Faulty | HIGH); to reverse it we need Bayes' rule.

Prediction multiplies the belief vector by the matrix. If today's belief is [Healthy 0.8, Faulty 0.2], tomorrow's is [0.8·0.9 + 0.2·0.2, 0.8·0.1 + 0.2·0.8] = [0.76, 0.24].

Hidden Markov models

A hidden Markov model (HMM) adds observations to a Markov chain. The true state is hidden, but at each time step it produces an observation. An HMM has three ingredients: initial probabilities π (here 80% Healthy, 20% Faulty), the transition matrix T and the emission matrix O.

Four questions an HMM can answer

TaskQuestionOur motor after HIGH, HIGH
FilteringWhat is the state now?P(Faulty at t=2) ≈ 72.3%
PredictionWhat will the state be next?P(Faulty at t=3) ≈ 60.6%, before reading 3
SmoothingWhat was the state earlier, using later evidence too?P(Faulty at t=1) ≈ 67.7%
ViterbiWhich complete sequence of states is most likely?[Faulty, Faulty]
Worked example · filtering two HIGH readings
  1. Time 1, correct with HIGH. Healthy: 0.8 × 0.2 = 0.16. Faulty: 0.2 × 0.7 = 0.14. Normalise by 0.30 → [53.3%, 46.7%].
  2. Time 2, predict. Healthy: 0.533 × 0.9 + 0.467 × 0.2 ≈ 0.573. Faulty: 0.533 × 0.1 + 0.467 × 0.8 ≈ 0.427.
  3. Time 2, correct with HIGH. [0.573 × 0.2, 0.427 × 0.7] = [0.115, 0.299]. Normalise by 0.413 → [27.7%, 72.3%].

Filtering is always predict, then observe, then correct, then normalise. The motor's real condition may not have changed; our information has.

With long sequences there are too many paths to list, so the Viterbi algorithm keeps, for each state, only the best path ending there, using δt(j) = Oj(et) × maxi [δt−1(i) × Tij], and then backtracks. Filtering combines alternatives with a sum; Viterbi uses a max.

import numpy as np
T = np.array([[.9, .1], [.2, .8]])            # transitions: rows = current state
O = {"High": np.array([.2, .7]), "Normal": np.array([.8, .3])}
belief = np.array([.8, .2])                   # [Healthy, Faulty]
for t, reading in enumerate(["High", "High"]):
    if t > 0:
        belief = belief @ T                   # predict
    belief = belief * O[reading]              # correct with the evidence
    belief = belief / belief.sum()            # normalise
    print(t + 1, belief.round(3))             # 1 [0.533 0.467] · 2 [0.277 0.723]
Did you know?

For decades, most speech-recognition systems were built on HMMs, with hidden states for sounds and observations for acoustic features. Robots use the same filtering idea to estimate where they are from noisy distance sensors; the Kalman filter is its continuous-valued relative.

Myth

To get the best path, just take the most likely state at each time step.

Fact

The most likely individual states do not always form the most likely whole sequence. Viterbi optimises the path as a whole.

Remember
  • HMM = initial probabilities π + transitions T + emissions O.
  • Filtering: predict with T, weight by O, normalise. Prediction: multiply by T with no new evidence.
  • Smoothing uses future evidence for a past state; Viterbi finds the single best whole path.

Week 8 · Rational decisions and classical machine learning

The Land of Choices and Data

Data gives predictions. Utilities turn predictions into wise actions. A model that predicts well is not automatically a system that decides well.

In the eighth land a factory foreman asked Tulpar to decide when to repair the machines. "Here are a thousand records of temperature, vibration and breakdowns," he said. "Learn from the past," said Bürkit, "but do not stop at a prediction. Ask what each mistake would cost."

Expected utility

A utility is a number that says how much we like an outcome. The expected utility of an action averages the utilities of its outcomes, weighted by probability: EU(a) = Σ P(o | a) · U(o). The principle of maximum expected utility (MEU) says a rational agent picks a* = argmaxa EU(a).

Worked example · two projects
  1. Project A: 90% success (+100), 10% failure (−20). EU = 0.9·100 + 0.1·(−20) = 88.
  2. Project B: 60% success (+200), 40% failure (−50). EU = 0.6·200 + 0.4·(−50) = 100.
  3. B is riskier but has higher expected utility, so MEU chooses B. A risk-averse agent, whose utility curve bends down for large losses, might still prefer A.
Worked example · when to repair a machine

Repair costs $2,000 and prevents failure. A failure costs $10,000. If we continue, the expected cost is p × $10,000.

  1. Repair when p × 10,000 > 2,000, that is, when p > 2,000 / 10,000 = 0.20.
  2. With p = 0.30, expected cost of continuing = $3,000 > $2,000, so repair.

The 20% threshold comes from the costs, not from the model's accuracy. If failures were more expensive, the threshold would drop.

From rules to learning

In traditional programming, people write the rules: "if temperature > 80 then alarm". In machine learning (ML), the algorithm learns a model ŷ = fθ(x) from examples, where x are the input features, θ the learned parameters and ŷ the prediction.

Classical supervised models

  • Linear regression predicts a number: ŷ = wx + b. Training finds w and b that minimise the mean squared error MSE = (1/n) Σ (yᵢ − ŷᵢ)². Example: if consumption = 5 × temperature + 100, then at 30°C the prediction is 250 kWh.
  • Logistic regression predicts a probability for a class: P(y = 1 | x) = σ(wᵀx + b), where the sigmoid σ(z) = 1 / (1 + e−z) squeezes any score into (0, 1). σ(0) = 0.5, σ(2) ≈ 0.88, σ(−2) ≈ 0.12. To turn the probability into a yes/no answer we choose a threshold τ; it does not have to be 0.5.
  • Naive Bayes classifies with Bayes' rule and the "naive" assumption that features are independent given the class: P(C | x) ∝ P(C) · Π P(xᵢ | C). It is fast, needs little data and works well for text such as spam filtering.
  • Decision trees learn readable if-then questions ("temperature > 70°C? vibration > 3?"). Deep trees can overfit.
  • Random forests train many trees on random samples of rows and features, then vote. This usually reduces variance and generalises better, at some cost in interpretability.
Worked example · Naive Bayes spam filter

P(spam) = 0.4. The word "free" appears in 30% of spam and 2% of normal mail; "meeting" appears in 5% of spam and 20% of normal mail. An email contains both words.

  1. Spam score: 0.4 × 0.30 × 0.05 = 0.0060
  2. Not-spam score: 0.6 × 0.02 × 0.20 = 0.0024
  3. P(spam | email) = 0.0060 / (0.0060 + 0.0024) ≈ 71%.

Unsupervised learning: K-means

K-means groups unlabeled points into K clusters: choose K centres, assign every point to its nearest centre, move each centre to the mean of its points, and repeat until nothing changes. It minimises J = Σk Σx∈Ck ||x − μk||². Scale the features first, or the feature with the biggest numbers dominates the distances. The algorithm finds groups; people still decide what the groups mean.

Measuring a classifier honestly

Worked example · 1,000 machines, 20 real failures
Predicted failurePredicted normal
Actually failedTP = 18FN = 2
Actually normalFP = 30TN = 950
  1. Accuracy = (TP + TN) / N = 968 / 1000 = 96.8%
  2. Recall = TP / (TP + FN) = 18 / 20 = 90%: how many real failures we caught.
  3. Precision = TP / (TP + FP) = 18 / 48 = 37.5%: how many alarms were real.
  4. F1 = 2PR / (P + R) = 2 × 0.375 × 0.9 / 1.275 ≈ 0.53

A lazy model that always says "normal" would score 98% accuracy here and catch zero failures. With rare events, look at recall and precision, not accuracy alone.

  • Split data into training (fit), validation (tune the model and threshold) and test (final, untouched estimate).
  • Overfitting: the model memorises noise and fails on new data. Data leakage: information from the test set or the future sneaks into training. Distribution shift: new data differs from training data.
  • Calibration: when a calibrated model says 70%, the event happens about 70% of the time. Decisions based on expected cost need calibrated probabilities.
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression

X = [[60,1.0],[65,1.5],[70,2.0],[72,2.2],[78,4.0],[82,4.5],[85,5.0],[88,5.5]]  # [temp °C, vibration]
y = [0, 0, 0, 0, 1, 1, 1, 1]                                                   # 1 = failed
model = make_pipeline(StandardScaler(), LogisticRegression()).fit(X, y)

Prediction and decision are two separate steps: the classifier gives a probability, and the cost model turns it into an action.

Did you know?

Arthur Samuel is usually credited with popularising the term "machine learning" in 1959, describing a checkers program that improved by playing against itself.

Myth

The model with the highest accuracy is always the best one to deploy.

Fact

A 95%-accurate model with 60% recall can be worse than a 92%-accurate model with 90% recall when missed failures are dangerous. Choose by consequences.

Remember
  • Rational action = maximise expected utility (or minimise expected cost).
  • Supervised learns from labels, unsupervised finds structure, RL learns from reward.
  • Evaluate on unseen data and pick metrics that match the cost of each mistake.

Week 9 · Perceptrons and neural networks

The Land of Neurons

Instead of writing features and rules by hand, a neural network learns its own internal representation from data.

The ninth land was a forest of glowing threads. Each thread carried a little signal, and each knot added up the signals it received and decided whether to pass one on. "This is how you will learn to see," said Bürkit. "Not one wise rule, but thousands of tiny ones that adjust themselves when they are wrong."

The perceptron

A perceptron is the simplest artificial neuron. It multiplies each input xᵢ by a weight wᵢ, adds a bias b, and passes the result through an activation function. For the classic perceptron the activation is a step:

z = w₁x₁ + w₂x₂ + … + b ŷ = 1 if z > 0, otherwise 0
Worked example · a perceptron that computes AND

Weights w₁ = w₂ = 1, bias b = −1.5.

  1. (1, 1): z = 1 + 1 − 1.5 = 0.5 > 0 → 1
  2. (1, 0) or (0, 1): z = −0.5 → 0; (0, 0): z = −1.5 → 0
  3. Change the bias to −0.5 and the same neuron computes OR.

The perceptron learning rule. Show an example, compare the prediction ŷ with the true label y, and nudge the weights: wᵢ ← wᵢ + η (y − ŷ) xᵢ and b ← b + η (y − ŷ), where η is the learning rate. If the prediction is right, nothing changes. If the classes can be separated by a straight line (they are linearly separable), this rule is guaranteed to find a separating line.

The XOR problem and hidden layers

XOR outputs 1 when exactly one input is 1. No single straight line separates (0,1) and (1,0) from (0,0) and (1,1), so one perceptron cannot learn it. Marvin Minsky and Seymour Papert made this limitation famous in 1969. The fix is to add a hidden layer:

Worked example · two layers compute XOR
  1. Hidden neuron h₁ = step(x₁ + x₂ − 0.5) computes OR.
  2. Hidden neuron h₂ = step(x₁ + x₂ − 1.5) computes AND.
  3. Output = step(h₁ − h₂ − 0.5): "OR but not AND". Check (1, 1): h₁ = 1, h₂ = 1, output z = −0.5 → 0. Check (1, 0): h₁ = 1, h₂ = 0, z = 0.5 → 1.
Try it · train a perceptron

Choose a logic gate and train with the perceptron rule (η = 0.2, starting from w = [0, 0], b = −0.1). Blue dots should end up on the shaded side of the line, gold dots on the other. AND and OR converge in a few epochs. XOR never does.

Multi-layer neural networks

A multi-layer perceptron (MLP) stacks layers: input → one or more hidden layers → output. Each neuron computes a weighted sum and applies a smooth, non-linear activation such as sigmoid, tanh or ReLU(z) = max(0, z). Without non-linear activations, many layers would collapse into one linear function. With them, a network with enough hidden units can approximate a very wide range of functions; this is the universal approximation result.

Worked example · one neuron's forward pass

Inputs x = [2, −1], weights w = [0.5, 0.3], bias b = 0.1.

  1. z = 0.5·2 + 0.3·(−1) + 0.1 = 1 − 0.3 + 0.1 = 0.8
  2. ReLU(0.8) = 0.8; sigmoid(0.8) = 1 / (1 + e−0.8) ≈ 0.69

How a network learns

  1. Forward pass: compute predictions from the inputs, layer by layer.
  2. Loss: measure the error, e.g. mean squared error for numbers or cross-entropy for classes.
  3. Backpropagation: use the chain rule of calculus to compute how much each weight contributed to the error (the gradient), starting from the output and moving backwards.
  4. Gradient descent: move every weight a little against its gradient, w ← w − η ∂Loss/∂w, the same idea as in Chapter 3.
  5. Repeat over many epochs (passes through the data), usually in small mini-batches.

Networks with many parameters can overfit. Common defences are a validation set with early stopping, dropout (randomly switching off neurons during training) and more data. Special architectures suit special data: convolutional networks (CNNs) share weights across an image to find edges, then shapes, then objects; recurrent networks and transformers handle sequences such as text and sensor streams.

from sklearn.linear_model import Perceptron
from sklearn.neural_network import MLPClassifier

X = [[0, 0], [0, 1], [1, 0], [1, 1]]
y_xor = [0, 1, 1, 0]

p = Perceptron(max_iter=1000).fit(X, y_xor)
print("perceptron:", p.predict(X))   # cannot get all four right

mlp = MLPClassifier(hidden_layer_sizes=(4,), activation="tanh",
                    solver="lbfgs", random_state=1, max_iter=2000).fit(X, y_xor)
print("MLP:", mlp.predict(X))         # [0 1 1 0] with a hidden layer
Did you know?

Frank Rosenblatt introduced the perceptron in 1958 and built it as a physical machine, the Mark I Perceptron. Deep learning took off in 2012, when the AlexNet network won the ImageNet image-recognition challenge by a large margin, trained on graphics processors (GPUs).

Myth

Artificial neural networks work just like the human brain.

Fact

They are loosely inspired by neurons, but they are mathematical functions trained with calculus. Real brains are far more complex and learn in different ways.

Remember
  • Perceptron: weighted sum + bias + step. It learns any linearly separable pattern, but not XOR.
  • Hidden layers with non-linear activations make networks far more expressive.
  • Training = forward pass → loss → backpropagation → gradient descent, repeated.

Week 10 · LLMs, generative AI and AI safety

The Land of Words and Responsibility

Machines can now write, draw and talk. The last lesson is how they do it, where they fail, and who is responsible.

In the last land stood a talking stone that answered any question in beautiful sentences. Tulpar asked it the height of Bäiterek. The stone answered confidently, and Bürkit, who had flown over the tower a hundred times, laughed. "It speaks well. That is not the same as speaking truly. A wise robot checks."

What a large language model does

A language model assigns probabilities to the next piece of text given the text so far: P(next token | previous tokens). Text is split into tokens, which are words or pieces of words. Each token becomes a vector of numbers called an embedding, and similar meanings end up with similar vectors. A large language model (LLM) is a very large neural network, usually a transformer, trained on huge amounts of text to predict the next token. It generates text one token at a time, sampling from its predicted distribution and appending the result.

Transformer and attention
Introduced in the 2017 paper "Attention Is All You Need". Attention lets every token look at every other token and decide which ones matter for its meaning, e.g. what "it" refers to.
Pre-training
Learning next-token prediction on a very large text corpus. This is self-supervised: the labels are simply the next words.
Fine-tuning and RLHF
Further training on examples of helpful answers, and reinforcement learning from human feedback, where human preferences are turned into a reward signal. This links back to Chapter 5.
Context window
How much text the model can read at once. Anything outside it is not "remembered".
Worked example · temperature when sampling

The model gives raw scores (logits) 2, 1 and 0 to the next words "steppe", "city" and "sea". The softmax turns scores into probabilities: pᵢ = ezᵢ/T / Σ ezⱼ/T, where T is the temperature.

Other generative models

  • Generative vs discriminative: a discriminative model learns P(label | input), e.g. "spam or not?". A generative model learns how the data itself is distributed, so it can produce new examples.
  • GANs (generative adversarial networks, 2014): a generator makes fake images and a discriminator tries to catch them. They improve by competing, a small game tree of their own (Chapter 4).
  • Diffusion models learn to remove noise step by step. To make an image, they start from pure noise and denoise it, guided by a text prompt.

Limitations you must know

Hallucination

An LLM can produce fluent, confident text that is false, including invented sources. It predicts likely words, not verified facts.

Bias

Models learn patterns, including unfair ones, from their training data, and can repeat stereotypes.

Outdated knowledge

A model knows only what was in its training data, up to a cutoff date, unless it is connected to search or documents.

Privacy and security

Pasting confidential or personal data into a public chatbot can leak it. Prompts can also be manipulated ("prompt injection").

AI safety: making AI do what we actually want

  • Alignment: the system's goals should match human intentions and values.
  • Specification gaming: an agent optimises the reward we wrote, not what we meant (Chapter 5).
  • Robustness: small changes or adversarial examples (inputs crafted to fool a model) should not cause dangerous failures; models should cope with distribution shift.
  • Human oversight: a person must be able to understand, correct and stop high-impact systems. A human who always clicks "accept" is not real oversight.
  • Transparency: people should know when they are dealing with AI and when content is synthetic.

Prohibited and required

  • Manipulative AI that distorts behaviour or pressures people into harmful decisions is prohibited
  • Users must be told when AI is used; synthetic results must be labelled

Copyright and data

  • AI-assisted works are protected only where there is a creative human contribution
  • Personal-data and privacy rules still apply to training and use

The lecture's practical playbook for any organisation has seven steps: inventory every AI system, classify its risk, autonomy and data sensitivity, assess privacy, IP, security and fairness, approve an accountable owner, deploy with controls, monitor incidents and drift, and review whenever the model, data, vendor, purpose or law changes. Elsewhere, the European Union's AI Act follows a similar risk-based approach.

Physical AI: where it all comes together

For students of Physical AI, the destination is robots like Tulpar. A modern robot perceives with neural networks (Chapter 9), tracks hidden states with filters (Chapter 7), plans routes with search (Chapter 2), decides under uncertainty with expected utility and MDPs (Chapters 5 and 8), and increasingly takes instructions in natural language through language models (this chapter). Safety and law decide whether it may be deployed at all.

Did you know?

ChatGPT, released in November 2022, reached an estimated 100 million users in about two months, according to an analysis by the bank UBS. At the time, that made it the fastest-growing consumer app on record.

Myth

An LLM looks answers up in a database, so if it says something confidently, it must be true.

Fact

An LLM generates text from patterns learned in training. Confidence is not evidence; important facts need checking against reliable sources.

Remember
  • LLMs predict the next token with transformer networks, then are fine-tuned, often with RLHF.
  • Temperature controls randomness; hallucination, bias and privacy are real limits.
  • Safe AI needs alignment, robustness, human oversight, transparency and legal compliance.

The whole map

AI history milestones

  1. 1950

    Alan Turing publishes "Computing Machinery and Intelligence" and proposes the imitation game, now called the Turing test.

  2. 1956

    The Dartmouth workshop gives the field its name: artificial intelligence.

  3. 1958

    Frank Rosenblatt introduces the perceptron.

  4. 1959

    Arthur Samuel's self-improving checkers program popularises the term "machine learning".

  5. 1966–72

    Shakey the robot at SRI combines perception, planning and action; A* (1968) is developed for it.

  6. 1969

    Minsky and Papert's book Perceptrons shows that one layer cannot learn XOR.

  7. 1980s

    Expert systems spread in industry; Judea Pearl develops Bayesian networks; backpropagation is popularised (Rumelhart, Hinton and Williams, 1986).

  8. 1989

    Chris Watkins introduces Q-learning.

  9. 1992

    TD-Gammon learns backgammon through self-play.

  10. 1997

    IBM Deep Blue defeats world chess champion Garry Kasparov.

  11. 2012

    AlexNet wins ImageNet and starts the deep learning boom.

  12. 2014

    Generative adversarial networks (GANs) are introduced.

  13. 2016

    AlphaGo defeats Lee Sedol at Go, 4–1.

  14. 2017

    "Attention Is All You Need" introduces the transformer.

  15. 2022

    ChatGPT brings large language models to the public.

  16. 2024

    The EU AI Act enters into force.

  17. 2025

    Kazakhstan adopts its Law "On Artificial Intelligence" (No. 230-VIII ZRK).

Glossary

Admissible heuristic
Never overestimates the true remaining cost. CH 2
Agent
Perceives its environment through sensors and acts through actuators. CH 1
Alpha–beta pruning
Skips game-tree branches that cannot change the minimax decision. CH 4
Backpropagation
Computes each weight's gradient with the chain rule, from output to input. CH 9
Bayes' theorem
P(H|E) = P(E|H)P(H)/P(E): updates belief with evidence. CH 6
Bayesian network
A DAG of variables with a conditional probability table per node. CH 6
Bellman equation
Value now = expected immediate reward + discounted value later. CH 5
BFS / DFS
Search that expands the shallowest / deepest node first. CH 2
Calibration
Predicted probabilities match observed frequencies. CH 8
CSP
Constraint satisfaction problem: variables, domains, constraints. CH 3
Discount factor γ
Weight given to future rewards, between 0 and 1. CH 5
Embedding
A vector of numbers that represents a token's meaning. CH 10
Evaluation function
Estimates how good a non-terminal game position is. CH 4
Expected utility
Probability-weighted average utility of an action's outcomes. CH 8
Expectimax
Game search where chance nodes average instead of minimising. CH 4
Exploration vs exploitation
Trying new actions to learn vs using the best known action. CH 5
Filtering
Estimating the current hidden state from evidence so far. CH 7
Frontier
The set of nodes waiting to be expanded in a search. CH 2
Gradient descent
Move parameters against the slope of the loss to reduce it. CH 3, 9
Hallucination
Fluent but false output from a generative model. CH 10
Heuristic
An estimate of the cost from a state to the goal. CH 2
Hidden Markov model
Hidden states with Markov transitions that emit observations. CH 7
Hill climbing
Local search that always moves to a better neighbour. CH 3
K-means
Clustering that alternates assigning points and moving centres. CH 8
Large language model
A huge transformer trained to predict the next token. CH 10
MDP
States, actions, transition probabilities, rewards and a discount. CH 5
Minimax
Value assuming both players play optimally. CH 4
Overfitting
Learning noise in the training data, so new data is predicted poorly. CH 8, 9
PEAS
Performance, Environment, Actuators, Sensors. CH 1
Perceptron
A neuron: weighted sum plus bias, then a step function. CH 9
Policy
A rule that says which action to take in each state. CH 5
Precision / recall
Share of alarms that are real / share of real cases caught. CH 8
Q-learning
Model-free RL that learns action values from TD errors. CH 5
Rational agent
Chooses the action with the best expected performance given its evidence. CH 1
RLHF
Reinforcement learning from human feedback, used to fine-tune LLMs. CH 10
Simulated annealing
Local search that sometimes accepts worse moves, less often as it cools. CH 3
Smoothing
Re-estimating a past hidden state using later evidence. CH 7
Transformer
A neural network built around attention; the basis of LLMs. CH 10
UCS
Uniform-cost search: expands the lowest path cost first. CH 2
Utility
A number expressing how desirable an outcome is. CH 1, 8
Viterbi algorithm
Finds the most likely complete sequence of hidden states. CH 7
Zero-sum game
One player's gain is exactly the other's loss. CH 4
